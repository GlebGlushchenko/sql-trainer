# SQL Lab — тренажёр SQL

Веб-тренажёр для практики SQL в стиле LeetCode: 134 задачи с автоматической проверкой, справочник с примерами и глоссарием, песочница и синхронизация прогресса между устройствами.

**Демо:** https://sql-trainer-five.vercel.app

## Возможности

- **134 задачи** трёх уровней сложности (69 лёгких, 48 средних, 17 сложных) по 14 темам: SELECT, WHERE, сортировка, агрегаты, GROUP BY / HAVING, JOIN, подзапросы, строки и даты, CASE, оконные функции, CTE (включая рекурсивные), UNION / INTERSECT / EXCEPT, INSERT / UPDATE / DELETE, DDL.
- **Автопроверка решений.** Запрос пользователя и эталонное решение выполняются на чистых копиях базы, результаты сравниваются. Названия столбцов не важны; порядок строк проверяется только там, где задача требует ORDER BY. Для задач на изменение данных сравнивается состояние таблиц после выполнения.
- **Статусы задач:** «Решено», «Не прошёл», «Не начато», счётчик попыток, прогресс по сложности и темам.
- **Подсказки и решения:** подсказки открываются по одной, эталонное решение скрыто за замком.
- **Справочник:** 14 разделов с синтаксисом и примерами, глоссарий из 36 терминов, поиск. Любой пример открывается в песочнице кнопкой «▶ Попробовать».
- **Песочница:** свободные эксперименты с учебной базой, по желанию с сохранением изменений между запусками.
- **Редактор** на CodeMirror: подсветка, автодополнение таблиц и столбцов (Tab — подставить), горячие клавиши.
- **Темы:** светлая, тёмная или как в системе.
- **Аккаунты:** вход через GitHub или по ссылке на email (Supabase), синхронизация прогресса и черновиков. Без входа всё работает локально в браузере.

Все запросы выполняются прямо в браузере на SQLite, скомпилированной в WebAssembly ([sql.js](https://github.com/sql-js/sql.js)) — сервер для SQL не нужен.

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl+Enter` | Запустить запрос |
| `Ctrl+Shift+Enter` | Отправить решение на проверку |
| `Tab` | Подставить слово из автодополнения |
| `Ctrl+Space` | Открыть автодополнение |
| `Alt+←` / `Alt+→` | Предыдущая / следующая задача |

## Учебная база данных

| Таблица | Описание |
|---|---|
| `departments` | Отделы компании |
| `employees` | Сотрудники (с руководителями, зарплатами, датами найма) |
| `customers` | Клиенты |
| `products` | Товары и остатки на складе |
| `orders` | Заказы со статусами `delivered`, `shipped`, `processing`, `cancelled` |
| `order_items` | Позиции заказов |

В данных специально есть NULL, одинаковые зарплаты, пустой отдел, клиенты без заказов и незаказанные товары — чтобы тренировать типичные ловушки. Схема и данные: [`src/db/schema.ts`](src/db/schema.ts).

## Запуск локально

Нужен Node.js 18+.

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:5173. Без настроенного Supabase кнопки входа нет, прогресс хранится в `localStorage`.

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер разработки |
| `npm run build` | Проверка типов и production-сборка в `dist/` |
| `npm run preview` | Просмотр production-сборки |
| `npm run verify` | Прогон всех эталонных решений на учебной базе |

## Облачная синхронизация (Supabase)

1. Создайте проект на [supabase.com](https://supabase.com) или через Vercel → **Storage → Create Database → Supabase**.
2. Выполните [`supabase/schema.sql`](supabase/schema.sql) в **SQL Editor**. Скрипт создаёт таблицу `progress` с Row Level Security: каждый пользователь видит только свои строки.
3. Укажите переменные окружения (локально — в `.env.local`, пример в [`.env.example`](.env.example)):

   ```env
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```

   Переменные интеграции Vercel (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` и т. п.) подхватываются автоматически — см. [`vite.config.ts`](vite.config.ts).
4. В **Authentication → URL Configuration** укажите адрес сайта в **Site URL** и добавьте `https://<ваш-домен>/**` в **Redirect URLs**.
5. Для входа через GitHub создайте [OAuth App](https://github.com/settings/applications/new) с callback URL `https://<project-ref>.supabase.co/auth/v1/callback` и включите провайдера в **Authentication → Sign In / Providers → GitHub**.

## Деплой

Репозиторий подключён к Vercel: каждый push в `main` автоматически публикует новую версию. Vercel сам определяет Vite; настройки сборки по умолчанию подходят.

## Структура проекта

```
src/
  components/     UI: список задач, экран задачи, справочник, песочница, редактор
  data/           задачи (problems-basic.ts, problems-advanced.ts) и справочник
  db/             схема учебной БД и движок выполнения и проверки запросов
  store/          прогресс (localStorage + синхронизация) и тема оформления
  cloud/          клиент Supabase и авторизация
supabase/         SQL-скрипт для облачной базы
scripts/          проверка эталонных решений
```

## Как добавить задачу

Добавьте объект в `src/data/problems-basic.ts` или `src/data/problems-advanced.ts`:

```ts
{
  title: 'Название',
  difficulty: 'easy', // 'easy' | 'medium' | 'hard'
  topic: 'JOIN',
  description: 'Текст задачи, поддерживается `код` и **жирный**.',
  hints: ['Подсказка 1', 'Подсказка 2'],
  solution: `SELECT ...;`,
  ordered: true,          // если важен порядок строк
  check: `SELECT ...;`,   // для INSERT/UPDATE/DELETE/DDL: запрос для сравнения состояния
}
```

Ожидаемый результат вычисляется из `solution` автоматически. После добавления запустите `npm run verify`.
